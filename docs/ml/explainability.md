# Recommendation Explainability & Match Score Formulation

## 1. The Match % Formulation

In the MoieRec user interface, recommendations feature a prominent **Match %** badge (e.g. `96% MATCH FOR YOU`).

### Crucial Principle: Not a Probability or Confidence Interval
- The Match % is **strictly a normalized presentation score**.
- It is **NOT** a calibrated Bayesian probability of user engagement.
- It is **NOT** a p-value or statistical confidence interval.
- It is a monotonically transformed percentile metric indicating relative affinity within the candidate pool for the active user context.

---

## 2. Multi-Component Normalization & Percentile Mapping

When recommendations are generated by a hybrid model combining disparate signals (content similarity, collaborative latent dot-products, popularity), raw scores cannot be directly summed because their scales and variances differ:

1. **Component-Level Normalization (Pre-Weighting):**
   Each raw signal component $s_k(u, i)$ for candidate movie $i \in \mathcal{C}$ is normalized across the active candidate pool using either min-max normalization or robust rank-percentile normalization:
   $$\tilde{s}_k(u, i) = \frac{\text{Rank}(s_k(u, i)) - 1}{|\mathcal{C}| - 1} \in [0.0, 1.0]$$
2. **Hybrid Score Formulation:**
   The unified utility score is a linear combination of normalized components:
   $$S(u, i) = \alpha \cdot \tilde{s}_{\text{content}}(u, i) + \beta \cdot \tilde{s}_{\text{collab}}(u, i) + \gamma \cdot \tilde{s}_{\text{pop}}(u, i) + \delta \cdot \tilde{s}_{\text{explore}}(u, i)$$
   where $\alpha + \beta + \gamma + \delta = 1.0$.
3. **Presentation Match Percentage:**
   The presentation Match % maps the hybrid score to the user-facing range $[60\%, 99\%]$ based on its percentile rank among all scored candidates:
   $$\text{MatchPercent}(u, i) = \text{round}\left(60 + 39 \cdot \frac{\text{Rank}(S(u, i)) - 1}{|\text{Top-}N| - 1}\right)$$
   This ensures that the top-ranked recommendation displays a compelling 96–99% affinity badge, while lower-ranked candidates scale gracefully.

## 3. Grounded Explanation Generation ("Because You Liked X")

MoieRec adheres strictly to **evidence-based explainability**. Generic or fabricated explanations are strictly prohibited.

### Explanation Criteria:
1. **Source Attribution Rule:**
   An explanation stating *"Because you liked Blade Runner 2049"* is generated **only if**:
   - The user has an explicit positive rating ($r \ge 4.0$) or bookmark for *Blade Runner 2049* in their profile history.
   - The item-item similarity between *Blade Runner 2049* and the recommended item exceeds a predefined affinity threshold $\tau_{\text{sim}} \ge 0.65$ in the content or collaborative latent space.
2. **Aesthetic Affinity Attribute Tags:**
   Reason chips (such as `"HIGH COSINE OVERLAP: SCI-FI / NOIR"`, `"DIRECTOR ALIGNMENT: DENIS VILLENEUVE"`, `"TEMPORAL ERA: 2010s"`) must directly reflect mathematical intersection sets between the seed item and candidate item features.
3. **No Hallucinated Copy:**
   Every explanation string is derived programmatically from registered reason codes (`REASON_CONTENT_SIMILARITY`, `REASON_COLLABORATIVE_NEIGHBOR`, `REASON_DIRECTOR_MATCH`, `REASON_GENRE_CLUSTER`).
